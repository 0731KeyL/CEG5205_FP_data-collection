# 离线训练与实时推理边界

离线数据流程允许使用完整 trial、事件中心窗口和增强数据。在线机械臂控制
或游戏交互必须使用因果数据，不能等待未来样本，也不能在执行时做数据增强。

## 两条流程

```text
离线：
完整 trial
→ 质量检查
→ 时间重采样
→ 事件中心窗口
→ 训练集增强
→ 模型训练与评估

在线：
实时 IMU 样本
→ 固定长度环形缓冲区
→ 因果窗口
→ 训练时约定的预处理
→ 模型推理
→ 平滑/阈值/状态机
→ 机械臂或游戏
```

## 延迟预算

目标端到端响应时间：

```text
希望：100–200 ms
可接受上限：250 ms
```

建议初始配置：

```text
采样间隔：20 ms
窗口长度：300–500 ms
推理周期：20–50 ms
模型推理目标：< 20 ms
输出平滑/去抖：50–100 ms
```

不能直接用“等待完整 1 秒或 2 秒 trial 后再分类”的方案控制实时设备。

## 因果窗口

离线事件中心窗口可能使用事件后的样本，因此不能直接视为实时窗口。
部署模型应使用：

```text
当前时刻以前的 N 个样本
```

如果必须使用更长的窗口，应改为：

- 动作起始检测；
- 短窗口增量分类；
- 多次预测多数投票；
- 只在置信度足够时触发离散动作。

连续运动控制应优先使用姿态或倾角直接映射，而不是等待分类模型输出。
分类模型主要用于抓取、释放、切换等离散事件。

## 训练与部署一致性

在线端必须与训练端保持一致：

- 通道顺序；
- 加速度/角速度单位；
- 采样率；
- 窗口长度和步长；
- 是否减重力；
- normalization 参数；
- 标签映射；
- 置信度阈值；
- 缺失数据处理方式。

在线端禁止重新拟合 normalization，必须读取 `normalization.npz`。

## 性能验收

数据交付方应提供：

- 窗口长度和推理步长建议；
- normalization；
- 通道及单位定义；
- 可选的固定因果窗口版本。

模型组应报告：

- 单次推理耗时；
- 从动作开始到第一次正确输出的延迟；
- 从网络发送到机械臂执行的端到端延迟；
- 误触发次数；
- 丢帧或超时时的安全回退行为。

若训练使用事件中心窗口，但在线只能拿到因果窗口，必须额外训练或验证
因果窗口模型，不能仅用离线准确率判断实时体验。
